# #501 V8 post-Canvas encoder-input diagnostic

`owned-vp8-product-v8-low-inputs` runs one actual UI main-software conversion for each frozen distribution, in separate browser contexts. The prior source is `be35f5fa89a60189475fe2ef7fd446e9fa18cef4`; the candidate owned module is `f962b9e803a014febc96d9a59bbab8faeb032866e837136c6afd8dd972fc4186` (the candidate Git source is bound separately in its build state and receipt). The existing V8 manifest fixes the 1920×1080 source, q60, 12 fps target cadence, scale 1 and smart skip off. This selector installs no numeric timing or resource probe. Capture and transfer overhead make its elapsed times unsuitable for the frozen performance gate.

The pinned prior **main** Emscripten loader calls the validation callback after its actual indexed heap-copy loop. The callback accepts only a copy whose completed count is `width × height × 3`; different-sized heap copies do not advance its successful-encode ordinal. The candidate wrapper reads the checked ABI2 input-lease response at phase 3 and its request immediately before `vp8_v2_begin`, after the product's host writes have settled. It checks generation, sequential frame ticket, request geometry, layout 4, stride, q60, byte length and WASM extent. It publishes the selected copy only when `begin` returns working status 10. No alternate encoder route is introduced.

Both paths retain successful encode indices 0, 19, 38, 57 and 76 (tickets 1, 20, 39, 58 and 77). Each captured image is **packed opaque RGB**, 5760 bytes per row and 6,220,800 bytes total. Five fresh host copies occupy 31,104,000 bytes, below the strict 32 MiB page-copy cap per backend/context. Raw chunks of at most 64 KiB (at most 87,384 base64 characters, plus the RPC envelope) are streamed to a private guest output `.rgb` file after conversion; page references are released per file and contexts are closed sequentially. The transfer does not establish physical-copy, GPU, RSS, Stop or retention behavior. Raw pixels and WebP outputs remain private controller artifacts, not tracked assets or uploads.

The JSON receipt binds input digest, V8 manifest digest, distribution source/tree/core and manifest identities, prior loader and WebP WASM, candidate owned WASM, layout, byte length, selected ticket and SHA-256 of each raw RGB file. It also retains each complete WebP and RIFF ANMF/native `ImageDecoder` result. A run requires 77 successful encoder inputs and 77 emitted ANMF frames on both sides; selected raw hashes must match pairwise. A mismatch remains an explicit diagnostic finding with both raw files retained, never a pass. This diagnoses whether the two actual browser routes feed the same post-Canvas pixels. It does not judge rate or decoded quality; use the pinned developer oracle and an independent decoder on these private artifacts for that separate analysis.

Run the selector through the Windows controller with a source-bound `dist`, pinned `validation/windows/prior-dist`, frozen `validation/windows/owned-vp8-inputs/v8.webm`, and `validation/windows/inputs/owned-vp8-product-v8-low-inputs.json` containing only `{ "scenario": "owned-vp8-product-v8-low-inputs" }`. Keep every failed receipt. This diagnostic does not change the existing V8 campaign or its gates.
