## Product baseline and boundaries

The primary oracle is shipped patched `wasm-webp@0.1.0`, not an updated codec:

- Patch SHA256: `bef378941329357206c2b92a9ed683d03a25ca0c9331dd09f664fe0392d0b6f5`.
- Installed WASM SHA256: `4d438a73dfe550d608d6b89eee34ea9374d58d3ffa0355218766281fc9a76c22` (482273 raw bytes).
- Patched ESM glue SHA256: `75b19521738cd76144ae58442dbcdf7da3ff61ca0574a334f0079afc705f741c`.

Manifest, lock, patch and built executable hashes are retained with each candidate
receipt. The existing dist was bound to `f2d6bf67`, so it is excluded from the
current delivery baseline. The clean baseline `build:ci` passed. Its executable inventory and prospective
byte budgets are frozen in `501-owned-vp8-v2-baseline-assets.json`: initial static
JS closure 214046 raw / 65480 gzip bytes, deferred/background executables 1055557
raw / 382738 gzip bytes, all executable files 1269603 raw / 448218 gzip bytes.
Compression is independent gzip level 9, mtime zero. This is a build inventory,
not observed wire traffic. Initial gzip may grow at most 5% (68754 bytes); total
gzip/raw and deferred/background gzip must not exceed this baseline. Owned VP8
WASM is capped at the removed component's 482273 raw / 184377 gzip bytes. The
linear-capacity ceiling is 192 MiB, additionally subject to aggregate admission.

The UI WebP flow explicitly enters the main-thread pipeline, which selects
parallel Canvas Worker, serial Canvas, then software. The separate conversion
Worker also contains a software encoder path. `webp-encoder-service.ts` currently
copies packed RGB into the Emscripten singleton, extracts VP8 from still RIFF,
and feeds the owned animation mux. Both software call sites must be covered by
integration/removal; native results cannot qualify the new software encoder.

Core input contract: opaque 8-bit sRGB code values in checked packed RGB or
RGBA/RGBX/BGRA/BGRX records with width, height, byte stride and explicit layout.
Alpha layouts require every visible alpha byte to be 255; X bytes are ignored.
No implicit premultiplication, alpha compression or ICC reinterpretation. Preserve
the product's validated Canvas geometry/color transform and mux ICC behavior.
Visible dimensions are independent of replicated macroblock padding. Preserve
VP8's 16383-axis representation limit and the product's 10066329-pixel frame cap;
per-frame admission must additionally fit the unchanged aggregate envelope.
The prototype's 2048-axis/4194304-pixel/16-MiB-input/4-MiB-output limits are
engineering-only until replaced by checked resource admission, not product limits.

Keep quality intent q60/q75/q85 separate from low/medium/high cadence 12/18/30
FPS. Fix scale, FPS, smart-skip, selected frames, timing, loops and output
ownership between variants. Byte-identical compressed-frame deduplication remains
required, independent of prior frames/jobs.

## Prospective fixtures and gates

The old 15 controls remain regression/tuning controls, never held-out acceptance.
Tuning adds grayscale sweeps, horizontal/vertical ramps, colored text, chroma
edges, photographic crops and seeded noise. Correctness-only fixtures include
one-hot coefficients at all positions/signs/categories, zero runs, empty blocks,
skip transitions, Y2/B_PRED transitions, predictor edges, every modulo-16
remainder, 1x1/one-row/one-column, malformed records, repeated state and limits.
They may diagnose defects without constituting quality acceptance.

Held-out generators, seeds, external source licenses and decoded frame hashes are
frozen in `501-owned-vp8-v2-fixtures.json`, generated by
`scripts/test/owned-vp8-v2-fixtures.ts`. The eight tuning fixtures include the old
fifteen pattern/preset controls; fifteen distinct held-out fixtures include an
actual CC0 photograph, actual CC0 video frames and a duplicate hold. Include distinct text/edge/gradient/
photo/noise/video classes, tiny/odd and admitted large geometry, temporal changes,
duplicate holds and ICC/color controls. Do not use a held-out failure to retune
and re-label the same cohort as fresh acceptance. The held-out manifest and clean delivery inventory complete M0; subsequent
measurement candidates must identify their exact source and compiled module.

For every fixture/preset: PSNR >= primary baseline - 1 dB, SSIM >= baseline -
0.01, encoded bytes <= max(1.25 * baseline, baseline + 128 bytes). Report each
content class separately; handle exact/zero-MSE images explicitly, never accept
NaN arithmetic. Color conversion/sampling error and residual error are separate.
A complete correct but slow/large encoder is PARTIAL, not adoption or rejection
of the entire program. Keep prospective thresholds fixed for a measured candidate.

Whole-product median increase <= max(5% of baseline median, 20 ms); retain any
stricter applicable gate. Balance/interleave normally five samples per variant
and first/warm condition, retain all samples and median/range/MAD, and exclude
output verification from timing. Codec-only fixed-pixel and whole-product
fixed-video conditions are separate. Record source/build/settings/input/cache
identities, copied bytes and retained capacity. Accounting is not browser/GPU
peak or proof of physical zero-copy.

Active-work Stop-to-idle <=500 ms, with actual owned encoding observed; no stale
or cancelled publication; new-request same-document recovery. A failed/cancelled
job never automatically retries under another backend. Force the software route
and attest actual compiled module execution. Independently decode complete
animations, including timing/order/loops/holds/geometry/color and temporal output.

## Resources and adoption

Preserve 512 MiB conversion, 128 MiB demux reserve, 192 MiB frame reserve and
96 MiB WebP output policy. Account for simultaneous input/padded YUV/reconstruction/
coefficients/modes/contexts/partitions/finalization/host copies. Charge reserved
linear capacity once; do not add its contained slots again. ABI2 admission must
reject before allocation; no leased destination may grow/release/reuse during a
pending asynchronous write. Arithmetic output must be finalized before leasing.
New production Cargo dependencies: zero. Dense bounded records and bounded
host-task-yielding stages precede performance acceptance.

The candidate remains absent from production routes/assets until M2/M3/M4 pass.
M5 then removes reachable wasm-webp runtime, loaders/chunks/declarations/copies,
classification and runtime-only patch handling; a pinned dev oracle may remain.
Verify main/Worker/service-worker execution, offline/update recovery, MIME/CSP,
notices and initial/deferred/total delivered bytes separately from memory/wire.
Exact-head local/CI/security review and protected integration are required.
JavaScript/Actions CodeQL is not Rust coverage. Actual provider source and served
bytes are separate deployment evidence. Real Safari/mobile remain UNVERIFIED
until observed; managed WebKit is not Safari. Concrete missing-platform impact
must follow the existing acceptance policy without blocking independent work.

## Metric definition addendum before held-out measurements

`scripts/test/owned-vp8-v2-compare.ts` uses PSNR over all RGB bytes and FFmpeg's
SSIM filter on planar RGB (`gbrp`). For a dimension below eight pixels, only the
metric input is nearest-neighbor replicated to a minimum of eight; encoder input
and decoded visible geometry are unchanged. This prevents undefined tiny-window
statistics and applies identically to baseline and candidate. Exact zero-MSE
images use an explicit exact flag; a finite candidate cannot pass against an
exact baseline through Infinity/NaN subtraction. Thresholds remain unchanged.
These fixed-pixel checks do not qualify product timing, animation or memory.

- External reference discrepancy, unchanged: RFC 6386 section 13.3's illustrative

  table and sets `prevCoeffWasZero` unconditionally. The detailed table/narrative
  and independent libwebp decoder agree that plane 0 skips DC, plane 1 is Y2,
  and only a zero coefficient suppresses the following EOB branch. `residual.rs`
  follows those verified semantics; whole-frame native VP8/libvpx reconstruction
  tests check them. No modification to the external RFC is claimed.

No other confirmed repository documentation/code conflict was found in the
inspected VP8, runtime-route, resource-policy and build-convention scope.
